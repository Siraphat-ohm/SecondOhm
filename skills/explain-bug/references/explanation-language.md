# Re-pitch

Apply the explanation principles from Matt Pocock's [`wait-what`](https://github.com/mattpocock/skills/tree/main/skills/productivity/wait-what) skill to every reader-facing explanation.

1. **Set context before mechanism.** Open with what exists, why it matters to this reader, and the question the page answers. Then explain the execution or causal path.
2. **Use the repository's ubiquitous language.** Read the relevant `CONTEXT.md` before drafting. When `CONTEXT-MAP.md` identifies a more specific context, follow it. Reuse those terms exactly; define a code term or abbreviation before its first use. When neither file exists, use the user's and source code's established terms.
3. **Write in ASD-STE100 Simplified Technical English.** Use short, direct sentences and familiar words. Give one main action per sentence. Name the actor that performs each action.
4. **Re-pitch when context changes.** Before a new subsystem, state, or failure boundary, give the reader the minimum context needed to understand the next claim.

**Completion:** A reader new to the repository can explain the page's opening summary and each transition without translating project vocabulary.
